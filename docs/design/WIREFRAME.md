## Overview

MCM 제품을 **자기 사진 위에서** 입어보는 서비스. 회원이 전신 사진을 한 번 올려 **기준 이미지**로 변환해 두면, 이후 제품을 고를 때마다 그 위에 제품이 올라간 **착용 이미지**를 만들어 보여준다.

**핵심 사용자**: MCM 해커톤 심사위원과 팀 내부. 첫 방문에 설명 없이 5분 안에 자기 사진으로 결과를 봐야 한다.

**상위 과업(JTBD)**: *"이 가방이 내 몸에 어떤 크기로 보이는지 알고 싶다. 그리고 여러 개를 바꿔가며 비교하고 싶다."* — 이 문장의 뒷절이 배치를 정한다. 비교가 목적이므로 **제품을 바꾸는 동작이 화면에서 가장 가까워야** 한다.

**이번 패스 미사용 컴포넌트**: 없음. DESIGN.md의 13개 컴포넌트가 모두 배치됐다.

## User Flows

**F1 · 첫 방문 (가장 중요 — 심사장에서 이 흐름을 탄다)**
```
가입 → 신체 정보 입력(키·몸무게) → 사진 올리기 → [기준 이미지 생성 대기 ~30초]
     → 기준 이미지 확인 → 착용 화면 → 제품 클릭 → [착용 이미지 생성 대기 ~15초] → 결과
```

**F2 · 재방문**
```
로그인 → 착용 화면 (마지막에 쓰던 사진이 선택된 상태) → 제품 클릭 → 결과
```

**F3 · 제품 비교 (이 서비스의 값어치)**
```
착용 화면 → 제품 A 클릭 → 결과 → 제품 B 클릭 → 결과 → 제품 A 다시 클릭 → [저장돼 있어 즉시]
```
> 세 번째 스텝이 핵심이다. **한 번 본 제품은 즉시 다시 뜬다**(PRD v2 「착용 이미지 재사용」). 화면은 이 즉시성이 드러나게 만든다 — 되돌아왔을 때 로딩바가 보이면 안 된다.

**F4 · 결과가 마음에 안 들 때**
```
착용 이미지가 이상함 → [다시 만들기] → 새 결과
기준 이미지 자체가 이상함 → 사진첩 → [기준 이미지 다시 만들기] → 확인 후 딸린 착용 이미지 전부 삭제됨
```
> F4의 두 번째 갈래는 **파괴적 동작**이다. 눌리기 전에 무엇이 사라지는지 화면에서 알려야 한다.

### 착용 화면 `/`

**목적**: 사진 하나와 제품 하나를 골라 착용 이미지를 본다. 그리고 제품을 바꿔가며 비교한다.

**존 구조** (PC — 우선순위 순)

```
┌──────────────────────────────────────────────────────────────┐
│ Z0  [PageTitle MTM]                   [내 정보] [로그아웃⚠B2] │  전역 크롬
├──────────────────────────────────────────────────────────────┤
│ Z1  [SectionTitle 내 사진]                        [전체 보기] │
│     [PhotoThumb▨선택] [PhotoThumb▨] [PhotoThumb▨] [+ 올리기]  │  가로 1줄
├────────────────────────────────┬─────────────────────────────┤
│ Z2                             │ Z3 [SectionTitle 제품 128]   │
│                                │                  [전체 보기] │
│      ┌──────────────────┐      │  ┌────────┐ ┌────────┐      │
│      │                  │      │  │▨Tile   │ │▨Tile   │      │
│      │   LookStage      │      │  │이름     │ │이름     │      │
│      │   ▨ 착용 이미지   │      │  │$1,250  │ │$980    │      │
│      │                  │      │  └────────┘ └────────┘      │
│      │                  │      │  ┌────────┐ ┌────────┐      │
│      └──────────────────┘      │  │▨       │ │▨       │      │
│                                │  └────────┘ └────────┘      │
│   [제품명 · SpecTag           │      (세로 스크롤)           │
│    14.2 × 11.8 IN]             │                             │
│   [다시 만들기] [IconButton ×]  │                             │
└────────────────────────────────┴─────────────────────────────┘
        Z2 = 유동폭 (최소 480px)      Z3 = 고정 340px
```

**위계**: Z2(착용 이미지)가 가장 크다 — 화면 높이의 60% 이상. Z1은 얇은 띠(썸네일 72px). Z3는 고정폭이라 Z2가 화면이 넓어질수록 커진다. DESIGN.md 시금석대로 **UI를 지우면 사람과 가방만 남는다.**

**Z2 안에는 아무것도 겹치지 않는다** — 제품명·태그·버튼은 전부 무대 **바깥 아래**에 놓는다(DESIGN.md LookStage 규칙).

**반응형**

| 폭 | 배치 |
|---|---|
| ≥1200px | 위 그대로 (Z3 340px 고정) |
| 768~1199px | Z3를 280px로 좁히고 제품 타일 1열 |
| <768px (모바일 = C안) | **세로 1열로 접힘** — Z0 → Z1(가로 스크롤 썸네일) → Z2(전체폭) → Z3(**가로 스크롤 타일 1줄**) |

모바일에서 Z3가 세로 그리드가 아니라 **가로 스크롤 한 줄**인 이유: 착용 이미지를 보면서 엄지로 제품을 넘길 수 있어야 한다. 세로 그리드면 결과가 화면 밖으로 밀려난다.

**상태 화면**

| 상태 | 화면 |
|---|---|
| 사진 없음 | Z1이 `EmptyState` — *"먼저 전신 사진을 올려주세요"* + `[사진 올리기]`. Z2·Z3는 비활성(흐림) |
| 기준 이미지 생성 중 | Z1의 해당 썸네일 자리에 `ProgressBar` + *"기준 이미지를 만드는 중"*. Z2는 `EmptyState` |
| 제품 미선택 | Z2가 `EmptyState` — *"오른쪽에서 제품을 골라보세요"* (모바일: *"아래에서"*) |
| 착용 이미지 생성 중 | Z2 자리에 `ProgressBar` + *"착용 이미지를 만드는 중"*. **Z3는 계속 조작 가능**(다른 제품 클릭 시 요청 교체) |
| 생성 실패 | Z2가 `EmptyState` — 무엇이 실패했는지 한 줄 + `[다시 시도]` |

| 긴 한글 제품명 | Z2 하단 캡션은 두 줄까지 흐르고 그 이상은 말줄임. Z3 타일 이름은 **한 줄 말줄임** |

| focus | 모든 조작 요소에 1px 검정 외곽선. 사진첩·제품 목록은 방향키로 이동 가능 |

### 사진첩 `/photos`

**목적**: 사진을 올리고, 기준 이미지가 제대로 나왔는지 크게 확인하고, 아니면 다시 만든다.

```
┌──────────────────────────────────────────────────────────────┐
│ [PageTitle 내 사진]                              [+ 사진 올리기]│
├──────────────────────────────────────────────────────────────┤
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐        │
│  │ ▨ 원본        │  │ ▨ 원본        │  │ ▨ 원본        │       │
│  │ ▨ 기준 이미지  │  │ [ProgressBar]│  │ [EmptyState  │       │
│  │              │  │ 만드는 중     │  │  실패]        │       │
│  │ [다시 만들기] │  │              │  │ [다시 시도]   │       │
│  │ [삭제]        │  │              │  │              │       │
│  └──────────────┘  └──────────────┘  └──────────────┘        │
│         (2열 그리드 · 모바일 1열)                              │
└──────────────────────────────────────────────────────────────┘
```

**카드 하나 = 원본 사진 + 기준 이미지 나란히.** 둘을 같이 보여주는 이유는 *"내 얼굴이 맞나"*를 판정하려면 원본과 대조해야 하기 때문이다(ADR 0001 프리모템이 짚은 위험).

**[다시 만들기]를 누르기 전에 경고를 띄운다** — *"이 사진으로 만든 착용 이미지 N장이 함께 삭제됩니다."* 파괴적 동작이므로 확인 단계를 **구조로** 넣는다(닐슨 H5 에러 예방).

**상태**: 사진 0장이면 페이지 전체가 `EmptyState`. 기준 이미지 생성 중/실패는 카드 안에서 표시.

### 제품 목록 `/products`

**목적**: 128개를 한눈에 훑는다.

```
┌──────────────────────────────────────────────────────────────┐
│ [PageTitle 제품]                                    128개     │
├──────────────────────────────────────────────────────────────┤
│  ┌──────┐┌──────┐┌──────┐┌──────┐                           │
│  │▨Tile ││▨Tile ││▨Tile ││▨Tile │   4열 (PC)                 │
│  │이름   ││이름   ││이름   ││이름   │   2열 (태블릿)             │
│  │[Tag] ││[Tag] ││[Tag] ││[Tag] │   2열 (모바일)             │
│  │$가격  ││$가격  ││$가격  ││$가격  │                           │
│  └──────┘└──────┘└──────┘└──────┘                           │
│         ( ...한 페이지에 32개 )                                │
│                                                              │
│              [← 이전]  1  **2**  3  4  [다음 →]                │
│                    32개씩 · 4페이지                            │
└──────────────────────────────────────────────────────────────┘
```

**페이지네이션**: 한 페이지에 **32개**(4열 × 8줄), 총 **4페이지**. 128을 32로 나누면 딱 떨어져 마지막 페이지가 비지 않는다.

- **새 컴포넌트를 만들지 않는다** — 이전/다음은 `OutlineButton`, 번호는 `label` 타이포 텍스트다. 현재 페이지는 색이 아니라 **굵기와 밑줄**로 표시한다(DESIGN.md: UI에 색을 쓰지 않는다).
- **착용 화면 Z3에는 페이지네이션을 넣지 않는다.** 거기는 세로 스크롤 그대로다 — 제품을 연달아 눌러보는 비교 흐름(F3)에서 페이지를 넘기게 하면 흐름이 끊긴다. **전체 목록과 착용 화면의 목록은 다른 물건이다.**

> ⚠ **목록 타일의 착용 방식 태그는 아직 없다.** #28에서 백엔드에 필드가 없어 걷어냈고, 이후 `ProductDetailResponse` 에 `wearType` 이 생겨 **제품 상세에는 #34에서 복구**했다. 다만 **목록 응답(`ProductResponse`)에는 여전히 없어** 타일에 붙이지 못한다.
> 원래 이 태그가 **검색·필터 없이 훑을 수 있게 하는 유일한 단서**였으므로, 목록을 훑는 수단은 지금 제품명·가격·제품 컷뿐이다. 목록 응답에 `wearType` 을 추가해달라고 요청해야 U6(아래 UX 감사)가 풀린다. 필터는 PRD 범위 밖이라 만들지 않는다.

**타일 클릭 → 제품 상세 `/products/:id`로 이동.**

> ⚠ 착용 화면(`/`) 우측 Z3의 타일은 **다르게 동작한다** — 거기서는 상세로 가지 않고 **바로 착용 이미지를 만든다.** 비교 흐름(F3)이 이 서비스의 값어치인데, 제품을 볼 때마다 상세를 거치면 그 흐름이 끊긴다. **같은 컴포넌트가 놓인 자리에 따라 다른 곳으로 간다** — 3단계에서 헷갈리기 쉬운 지점이라 여기 못박는다.

**상태**: 로딩 중 `ProgressBar` 한 줄. 실패 시 `EmptyState` + `[다시 시도]`. 긴 이름은 한 줄 말줄임.

```
│                                │  · … (긴 목록, 흐름)         │
└────────────────────────────────┴─────────────────────────────┘
        좌 = 유동폭                    우 = 고정 380px
```

**위계**: 제품 컷이 왼쪽 전체를 차지하고, 오른쪽은 위에서부터 **이름 → 가격 → 착용 방식 → 크기 → 입어보기 → 상세** 순. **크기를 입어보기 버튼 바로 위에 두는 이유**는 이 서비스가 파는 것이 *크기 감*이기 때문이다 — 숫자를 본 직후에 "그럼 내 몸엔?"으로 넘어가게 한다.

**치수는 인치와 cm를 나란히** 표기한다. 원본 데이터는 인치인데(`Approximately D x W x H inches`) 한국 사용자는 cm로 감을 잡는다.

**반응형**: <768px에서 세로 1열 — 제품 컷 → 이름·가격·태그 → 크기 → 입어보기 → 상세. **`[이 제품 입어보기]`는 모바일에서 화면 하단에 고정**(스크롤해도 항상 보이게).

**상태**

| 상태 | 화면 |
|---|---|
| 로딩 | `ProgressBar` 한 줄 |
| 없는 SKU | `EmptyState` — *"제품을 찾을 수 없습니다"* + `[제품 목록으로]` |
| 제품 컷이 1장뿐 | 썸네일 줄을 감춘다 (빈 줄을 남기지 않는다) |
| 스트랩 데이터 없음 | 그 줄만 생략 (128개 중 37개가 결측 — PRD 데이터 사실) |
| 긴 상세 목록 | 자르지 않고 흐르게 둔다. 최대 폭 60자 |

## Do's & Don'ts (structural)

**Do**

- 착용 이미지 영역을 화면에서 가장 크게 둔다 — 이 서비스는 그것을 보러 오는 곳이다.
- 제품을 바꾸는 동작을 착용 이미지에서 **한 번의 클릭 거리**에 둔다(비교가 목적이므로).
- 모든 실패 화면에 **다음 행동 버튼**을 둔다 — 막다른 길을 만들지 않는다.
- 파괴적 동작(기준 이미지 다시 만들기)은 **누르기 전에** 무엇이 사라지는지 알린다.
- 모바일에서 제품 목록은 **가로 스크롤**로 접는다.

**Don't**

- **데이터·동작이 필요한 걸 조용히 그리지 마라.** 이 문서의 `⚠동작경계`(B1·B2·D3)가 그 표시이며, 개발 체인 확인 없이 3단계에서 구현하면 데이터 없는 화면이 된다.
- 착용 이미지 위에 버튼·뱃지를 겹치지 않는다 — 조작은 무대 **바깥**에 둔다.
- 생성 중이라고 제품 목록을 잠그지 않는다 — 비교 흐름이 끊긴다.
- 저장된 착용 이미지에 로딩바를 띄우지 않는다.
- 검색·필터·정렬을 만들지 않는다 — PRD 범위 밖이다.
- 화면 깊이를 2단 넘게 만들지 않는다.
